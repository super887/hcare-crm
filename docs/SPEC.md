# 바디케어·운동 지도 고객관리 웹앱 (Hcare CRM) 전체 설계서 (SPEC)

> **목적**: 위시켓 외주 지원용 인터랙티브 데모(11/2 마감 전 제출) 및 수주 후 최종 납품(11/23 정부 창업지원사업 시연)을 위한 단일 기준 설계서(Single Source of Truth)입니다.
> 다른 모델(Claude Sonnet, Gemini Flash 등)로 전환하여 개발할 때 항상 이 문서와 `supabase/schema.sql`을 먼저 읽도록 지시하세요.

## 1. 프로젝트 핵심 전략 (데모 수주 필승 포인트)

발주자(14년 경력 물리치료사 창업자, 비개발자)가 데모 링크를 열었을 때 **로그인 없이도 3초 만에 모든 화면을 체험**할 수 있어야 합니다.

1. **원클릭 역할 전환 바 (Demo Role Switcher)**
   - 화면 상단 고정 배너에서 `[관리사 화면 (PC/태블릿)]` ↔ `[관리자 설정 화면]` ↔ `[고객 화면 (모바일 뷰)]`를 클릭 한 번으로 즉시 전환할 수 있게 구현합니다.
   - 실제 납품 시에는 Supabase Auth(`role` 기반)로 분리되지만, 데모에서는 발주자가 번거롭게 로그아웃/로그인하지 않고도 전체 흐름을 한눈에 시연해 볼 수 있게 합니다.
2. **상태 실시간 연동 (End-to-End Flow)**
   - 관리사 화면에서 관찰 항목 체크 → 추천 프로그램 선택 → 홈운동 배정 및 저장을 누르면, **즉시 `[고객 화면]`과 `[관리 이력]`에 반영**되도록 구성합니다.
3. **물리치료 도메인 맞춤 샘플 데이터 (가짜 데이터 명시 안내 포함)**
   - 발주자가 임상 전문가이므로 터무니없는 데이터 대신 실제 현장 용어(예: `경추 회전 제한`, `상부승모근·견갑거근 과긴장`, `라운드숄더`, `흉추 가동성 저하`, `진자 운동`, `벽 슬라이드 운동` 등)를 초기 시드 데이터로 넣되, 화면 상단에 *"예시 데이터이며 관리자 화면에서 대표님이 직접 기준을 수정·추가할 수 있습니다"* 안내 배지를 표시합니다.
4. **인터랙티브 바디 맵 (Visual Body Map - 수주 결정적 킬러 킥)**
   - 단순 텍스트("상부승모근", "견갑거근") 나열을 넘어, 관찰 항목을 체크하는 즉시 인체 실루엣(앞면/뒷면 토글)에서 **타겟 근육 부위가 선명한 레드/코랄 펄스로 하이라이트**됩니다.
   - 관리사 화면(`/therapist`)뿐만 아니라 고객 모바일 알림장(`/my`)에도 "오늘 원장님이 집중 케어한 부위 리포트"로 동일하게 연동되어, 발주자(14년 경력 물리치료사)가 "고객 신뢰도와 재등록률을 극대화할 수 있는 현장형 시스템"임을 한눈에 체감하게 합니다.

## 2. 기술 스택 및 아키텍처

```
[Client Browser (PC / Tablet / Mobile)]
       │
       ▼
[Next.js 15 App Router (TypeScript + Tailwind CSS + shadcn/ui)]
  ├─ /therapist   : 관리사 전용 (고객 관리, 관찰 체크 및 맞춤 프로그램 매칭, 회차별 기록)
  ├─ /admin       : 관리자 전용 (관찰 항목 CRUD, 근육/프로그램 CRUD, 연결 기준 매핑, 계정 관리)
  ├─ /my          : 고객 전용 모바일 웹 (패키지 잔여 회차, 관리 이력, 배정된 홈운동 영상 및 수행 체크)
  └─ /api (or Server Actions) : 데이터 처리 및 향후 AI 추천 확장 엔드포인트
       │
       ▼
[Supabase (PostgreSQL + Auth + RLS)]
  ├─ Auth         : 이메일/패스워드 또는 간편 로그인 (Admin / Therapist / Client 권한 분리)
  ├─ Database     : 관계형 테이블 + Row Level Security (민감 건강정보 보호)
  └─ Demo Adapter : 데모 모드에서는 로컬 상태(Zustand/Context + LocalStorage)와 Supabase DB 모두 호환되도록 레이어 분리
```

## 3. 사용자 역할 및 권한 (RBAC)

| 역할 (`role`) | 접근 가능 경로 | 주요 권한 및 노출 범위 |
| :--- | :--- | :--- |
| **관리자 (`admin`)** | `/admin/*`, `/therapist/*` | 전체 고객/관리사 계정 관리, 관찰 체크리스트 항목 추가·수정, 근육·수기관리·홈운동 자료 관리, **체크 항목 ↔ 프로그램 연결 기준(Rule) 관리** |
| **관리사 (`therapist`)** | `/therapist/*` | 고객 등록/조회, 방문 회차별 관찰 항목 체크, 추천 근육·프로그램 가이드 조회(**내부 전용 노출**), 최종 관리 프로그램 및 홈운동 배정 저장 |
| **고객 (`client`)** | `/my/*` | 본인 패키지 현황(총 회차/잔여 회차) 조회, 방문 일자별 관리 요약 조회(내부 수기 가이드 비노출, 고객 안내용 요약만 노출), 배정된 홈운동 영상 시청 및 오늘 수행 완료 체크 |

## 4. 핵심 알고리즘: 규칙 기반(Rule-based) 맞춤 프로그램 추천 로직

공고의 핵심 요구사항(**2-2. 맞춤 관리 프로그램 제안**)은 AI가 아니라 **사전 설정된 연결 기준(Mapping Rule)**에 따라 동작하며, 향후 AI로 확장 가능한 구조여야 합니다.

### 4.1 입력 (Input)
- 관리사가 선택한 복수의 관찰 항목 ID 배열: `selectedObservationIds: string[]`
  - 예: `["obs_neck_rot_pain", "obs_round_shoulder", "obs_ winged_scapula"]`

### 4.2 매칭 및 가중치 산출 (Scoring & Filtering)
1. `observation_program_rules` (연결 기준 테이블)에서 `observation_id IN (selectedObservationIds)`인 모든 규칙을 조회합니다.
2. 각 관리 프로그램(`care_programs`)별로 매칭된 관찰 항목 수(일치도)와 우선순위 가중치(`priority_weight`: 1~5점)를 합산합니다.
   $$\text{MatchScore}(P) = \sum_{o \in \text{selected}} \text{weight}(o, P)$$
3. 매칭된 프로그램들을 `MatchScore` 내림차순(동점 시 매칭된 관찰 항목 개수순)으로 정렬하여 후보 카드로 표시합니다.
4. 각 후보 카드에는 다음 정보를 함께 렌더링합니다:
   - **왜 추천되었는지 (매칭 근거 태그)**: 선택한 관찰 항목 중 어떤 항목들과 연결되었는지 배지로 표시
   - **관련 타겟 근육 (`target_muscles`)**: 중점적으로 풀어야 할 근육 목록
   - **수기 관리 가이드 (`manual_therapy_guide`)**: 관리사 전용 수기 테크닉 및 압박 강도 가이드 (고객 비노출)
   - **주의사항 (`precautions`)**: 통증 양상별 금기사항
   - **연결된 홈운동 (`home_exercises`)**: 고객에게 배정할 수 있는 추천 운동 리스트

### 4.3 최종 선택 및 저장 (Output)
- 관리사가 추천 후보 중 1~N개의 프로그램과 고객용 홈운동을 체크하고 코멘트를 적어 `[관리 기록 및 홈운동 배정 저장]`을 클릭하면:
  1. `treatment_sessions` 테이블에 회차 기록 생성 (내부용 메모 + 고객 공개용 요약 분리 저장)
  2. `client_packages`의 사용 회차(`used_sessions`) 1 증가
  3. `assigned_exercises` 테이블에 고객이 모바일에서 볼 홈운동 자동 배정

## 5. 상세 화면 설계 (UI/UX 와이어프레임 명세)

### 5.1 관리사 화면 (`/therapist`) — PC·태블릿 최적화 (좌우 2단 또는 3단 분할)
- **좌측 사이드바 (고객 목록 및 검색)**
  - 고객 검색, 신규 고객 등록 모달 버튼
  - 고객 카드 선택 시 우측 메인 워크스페이스에 해당 고객 정보 로드 (현재 패키지 잔여 회차, 선호 강도, 주의사항 배지 표시)
- **메인 탭 1: 맞춤 관리 가이드 & 기록 작성 (핵심 화면)**
  - **[Step 1] 신체·움직임 관찰 체크리스트**: 부위별(경추/어깨, 흉추/견갑, 요추/골반, 하지) 아코디언 또는 탭으로 구성된 체크박스 그룹. 클릭 즉시 우측 후보 영역이 실시간 업데이트됨.
  - **[Step 2] 추천 근육 및 관리 프로그램 후보 + 인터랙티브 바디 맵 (BodyMap)**:
    - **중점 타겟 바디 맵 (Visual Body Map)**: 선택된 관찰 항목에 따라 앞면(Front)/뒷면(Back) 인체 실루엣에 관련 근육(승모근, 견갑거근, 능형근, 대흉근, 이상근, 햄스트링 등)이 실시간 붉은색 펄스로 하이라이트 표시됨. 클릭/호버 시 근육 의학 명칭 툴팁 제공.
    - 상단 요약 바: *"선택된 관찰 항목 N개 기준, 중점 타겟 근육: 상부승모근, 견갑거근, 소흉근"*
    - 추천 프로그램 카드 리스트 (일치도 높은 순 정렬, 상세 모달/아코디언으로 수기 관리법·주의사항 확인, `[이번 회차 적용]` 토글 버튼)
  - **[Step 3] 최종 선택 및 홈운동 배정 저장**:
    - 선택된 프로그램 요약
    - 배정할 홈운동 체크박스 (선택한 프로그램에 연결된 홈운동이 기본 체크됨)
    - 관리사 내부 기록(고객 비공개) & 고객 알림장 코멘트(고객 공개) 입력란
    - `[회차 기록 저장 및 고객 홈운동 발송]` 버튼
- **메인 탭 2: 고객 정보 및 방문 회차별 관리 이력**
  - 고객 기본 정보, 초기 상담 차트, 선호사항 수정
  - 타임라인 형태의 회차별 기록 조회 (1회차, 2회차... 당시 체크했던 관찰 항목, 시행한 프로그램, 고객의 홈운동 수행 달성률 표시)

### 5.2 관리자 화면 (`/admin`) — 대표님 직접 운영용
- **탭 1: 관찰 체크리스트 관리**: 부위 카테고리별 관찰 항목 추가/수정/비활성화
- **탭 2: 관리 프로그램 & 근육 자료실**: 프로그램명, 대상 근육 태그, 수기 관리 방법, 주의사항, 홈운동(유튜브/비메오 임베드 URL 또는 가이드 텍스트) 등록·수정
- **탭 3: 연결 기준(매핑 룰) 매트릭스 (핵심)**:
  - 특정 관찰 항목을 선택하면 연결된 관리 프로그램 목록이 나오고, 드래그나 체크박스로 손쉽게 연결을 추가·해제하거나 중요도(기본/핵심)를 바꿀 수 있는 직관적인 UI
- **탭 4: 계정 및 권한 관리**: 관리사/고객 목록 및 권한 등급, 개인정보/민감정보 동의 상태 확인

### 5.3 고객 화면 (`/my`) — 스마트폰 모바일 뷰 (Max-width 430px 프레임 제공)
- **데모 편의 기능**: PC에서 볼 때 스마트폰 베젤 프레임 안에 렌더링하여 발주자가 "고객 스마트폰에서는 이렇게 보입니다"를 직관적으로 확인 가능
- **상단 헤더**: 고객명, 이용 중인 패키지명, 프로그레스 바 (`잔여 7회 / 총 10회`)
- **오늘의 집중 케어 부위 바디 맵 리포트**:
  - 관리사가 오늘 회차에서 수기 관리한 타겟 근육이 강조된 모바일 최적화 바디 맵 표시 ("오늘 원장님이 집중 케어해 드린 부위입니다")
- **오늘의 맞춤 홈운동 카드**:
  - 관리사가 가장 최근 회차에 배정한 운동 목록
  - 운동 영상/이미지 미리보기, 따라하기 설명(세트/횟수/호흡법)
  - **`[오늘 운동 완료 체크]` 큰 버튼** (클릭 시 체크 애니메이션 + 수행 기록 저장 + 이번 주 달성률 게이지 상승)
- **나의 관리 이력 탭**:
  - 방문 일자별 받은 케어 요약(고객 눈높이 설명) 및 담당 관리사 코멘트 확인 (내부용 수기 가이드 및 민감 메모는 철저히 비노출)

## 7. 보안(민감정보) 및 향후 확장성 설계

1. **개인정보 및 신체 관찰 정보 보호**
   - 신체 통증·체형 관찰 기록은 개인정보보호법상 민감정보에 해당할 수 있으므로 고객 등록 시 `privacy_consent_at`(개인정보 및 민감정보 수집·이용 동의 일시) 필드를 필수로 기록합니다.
   - Supabase RLS(Row Level Security)를 통해 고객(`role = 'client'`)은 본인의 `client_id`와 일치하는 데이터만 `SELECT` 가능하며, `treatment_sessions`에서도 내부 가이드 칼럼은 뷰(View) 또는 API 레이어에서 제외하고 반환합니다.
2. **향후 AI 추천 연동 구조 (Phase 2 확장 대비)**
   - 현재 `src/lib/matching-engine.ts`의 `getRecommendedPrograms(observationIds, clientHistory)` 인터페이스를 추상화해 둡니다.
   - 추후 누적된 `treatment_sessions` 데이터(관찰 항목 조합 + 실제 관리사가 최종 선택한 프로그램 + 고객 호전도 피드백)를 프롬프트 컨텍스트 또는 임베딩으로 넘겨 OpenAI/Gemini API가 추천 사유를 생성하도록 함수 내부만 교체하면 UI 수정 없이 AI 서비스로 업그레이드됩니다.
3. **다지점 확장 대비 (`branch_id`)**
   - 모든 핵심 테이블(`clients`, `profiles`, `treatment_sessions`)에 `branch_id`(지점 식별자, 기본값 `'main'`) 칼럼을 미리 포함하여, 향후 2호점·3호점 확장 시 DB 재설계 없이 지점별 데이터 분리가 가능하도록 설계했습니다.
