> **핵심 원칙**: 설계 문서([`docs/SPEC.md`](file:///c:/Users/suwer/Downloads/Hcare/docs/SPEC.md))와 DB 스키마([`supabase/schema.sql`](file:///c:/Users/suwer/Downloads/Hcare/supabase/schema.sql))가 이미 최상위 모델(Argon)로 완성되어 파일로 저장되어 있습니다.

## 1. 작업 성격별 LLM 모델 추천 매트릭스

| 단계 / 작업 성격 | 추천 모델 (1순위) | 대안 모델 (2순위) | 추천 이유 |
| :--- | :--- | :--- | :--- |
| **전체 아키텍처 / DB 스키마 / 보안(RLS) 설계** | **Gemini 4 Argon** (또는 Claude Opus) | Claude Sonnet 5.5 | 첫 단추가 틀어지면 전체 재작업이 발생하므로 추론력이 가장 높은 모델 사용 (**현재 완료됨**) |
| **핵심 비즈니스 로직 & 상태 관리 (`matching-engine.ts`, `store.ts`)** | **Claude Sonnet 5.5** | Gemini 4 Argon | TypeScript 타입 정합성과 복잡한 배열/가중치 매칭 로직을 실수 없이 깔끔하게 작성함 |
| **메인 UI 화면 조립 (`/therapist`, `/admin`, `/my`)** | **Claude Sonnet 5.5** | Gemini 3.8 Flash | Tailwind CSS + shadcn/ui 레이아웃 구성 및 인터랙티브 상태 연결 능력이 가장 뛰어남 |
| **단순 UI 수정 / 문구 변경 / 모달 추가 / 반복 작업** | **Gemini 3.8 Flash** | Claude Sonnet 5.5 | 이미 만들어진 컴포넌트의 색상, 패딩, 텍스트, 샘플 데이터 추가 등은 Flash가 빠르고 한도 소모가 극히 적음 |
| **최종 검수 / 버그 디버깅 / 배포 전 점검** | **Gemini 4 Argon** | Claude Sonnet 5.5 | 전체 파일 간 의존성 충돌, 모바일 반응형 깨짐, 보안 누락 여부를 한 번에 점검 |

## 2. 11월 2일(지원 마감) 전 데모 완성 5단계 워크플로우

### Step 1. Next.js 프로젝트 초기화 및 핵심 데이터/매칭 엔진 구축 (예상 소요: 30분)
- **권장 모델**: `Claude Sonnet 5.5` (또는 `Gemini 3.8 Flash`)
- **목표**: Next.js + Tailwind 설정, 물리치료 도메인 샘플 데이터(`mock-data.ts`), 관찰 체크 → 프로그램 추천 알고리즘(`matching-engine.ts`), 전역 스토어(`store.ts`) 생성
- **복사해서 쓸 프롬프트**:
  ```text
  docs/SPEC.md와 supabase/schema.sql을 읽고 Step 1을 진행해줘.
  1. 현재 워크스페이스에 Next.js (App Router, TypeScript, Tailwind CSS, Lucide Icons) 프로젝트를 세팅해줘.
  2. src/types/hcare.ts에 스키마와 일치하는 TypeScript 타입들을 정의해줘.
  3. src/lib/mock-data.ts에 14년차 물리치료사 창업자가 봐도 감탄할 만한 현실적인 관찰 항목(경추/어깨, 흉추/견갑, 요추/골반, 하지 카테고리별 12개 이상), 관리 프로그램(대상 근육, 수기 관리 방법, 주의사항 포함 6개 이상), 홈운동(5개 이상), 연결 기준(Rule), 샘플 고객 4명 및 회차 기록 데이터를 작성해줘.
  4. src/lib/matching-engine.ts에 관찰 항목 복수 선택 시 가중치(priority_weight) 합산으로 관련 근육과 추천 프로그램을 정렬해 반환하는 함수를 구현해줘.
  5. src/lib/store.ts에 관리사/관리자/고객 화면이 실시간으로 데이터를 공유하고 LocalStorage에 유지되는 상태 관리(초기 데이터 리셋 기능 포함)를 구현해줘.
  ```

### Step 2. 상단 데모 역할 전환 바 & 관리사 핵심 화면(`/therapist`) 구현 (예상 소요: 1시간)
- **권장 모델**: `Claude Sonnet 5.5`
- **목표**: 공고의 최우선 요구사항인 **2-1(고객 관리/이력)** 및 **2-2(관찰 항목 체크 → 관련 근육·프로그램 후보 표시 → 최종 선택 저장)** 완벽 구현
- **복사해서 쓸 프롬프트**:
  ```text
  docs/SPEC.md의 5.1절을 참고해서 상단 데모 전환 바(Demo Toolbar)와 관리사 화면(/therapist)을 구현해줘.
  1. 상단 고정 바에서 [관리사 화면] / [관리자 설정 화면] / [고객 모바일 화면]을 원클릭으로 오갈 수 있고, '예시 데이터 안내' 및 '데모 초기화' 버튼이 있게 해줘.
  2. 좌측에는 고객 목록 검색, 신규 고객 등록 모달, 고객 선택 시 기본 상담 정보/선호사항/패키지 잔여 회차가 보이게 해줘.
  3. 메인 영역에서는 부위별 신체·움직임 관찰 항목을 복수 체크하면 우측에 즉시 중점 타겟 근육 배지들과 추천 관리 프로그램 후보 카드가 매칭 점수순으로 표시되게 해줘.
  4. [핵심 킬러 킥 - 바디 맵 연동]: 추천 후보 영역 상단(또는 관찰 체크 옆)에 `src/components/body-map/BodyMap.tsx` 컴포넌트를 배치하여, 추천된 타겟 근육(targetMuscles)들이 앞/뒤 인체 실루엣에 실시간 붉은색 펄스로 점등되게 연결해줘 (발주자 시연 시 시각적 만족도 극대화).
  5. 각 프로그램 카드에서 대상 근육, 수기 관리 방법(내부 전용 배지 표시), 주의사항, 연결된 홈운동을 상세 조회할 수 있게 해줘.
  6. 관리사가 최종 프로그램과 배정할 홈운동을 선택하고 내부 메모(고객 비공개)와 고객 안내 코멘트(고객 공개)를 입력해 저장하면 회차 이력에 추가되고 패키지 사용 회차가 반영되게 해줘.
  ```

### Step 3. 관리자 화면(`/admin`) & 고객 모바일 화면(`/my`) 구현 (예상 소요: 1시간)
- **권장 모델**: `Claude Sonnet 5.5`
- **목표**: 공고의 **2-3(프로그램 자료 관리, 연결 기준 직접 수정, 권한 관리)** 및 **2-4(고객 모바일 로그인/패키지 현황/홈운동 영상 및 수행 체크)** 구현
- **복사해서 쓸 프롬프트**:
  ```text
  docs/SPEC.md의 5.2절과 5.3절을 참고해서 관리자 화면(/admin)과 고객 화면(/my)을 구현해줘.
  1. /admin 화면:
     - 대표님이 개발 완료 후 직접 관찰 체크리스트 항목과 관리 프로그램(대상 근육, 수기 관리법, 홈운동)을 추가·수정할 수 있는 UI
     - [핵심] 특정 관찰 항목과 관리 프로그램 간의 연결 기준(매핑 Rule 및 가중치)을 클릭으로 즉시 추가·삭제할 수 있는 매트릭스 UI (여기서 수정하면 /therapist 추천 결과에 즉시 반영되어야 함)
     - 관리자/관리사/고객 계정 및 접근 권한 안내 탭
  2. /my 화면 (고객용 스마트폰 반응형 뷰):
     - PC에서 볼 때도 모바일 스마트폰 프레임(최대 폭 430px) 안에서 깔끔하게 보이도록 구성하고, 상단에서 테스트 고객을 바꿔볼 수 있게 해줘.
     - [신규] 상단에 '오늘의 집중 케어 부위 리포트'로 `BodyMap`을 컴팩트하게 표시하여 고객이 오늘 원장님께 관리받은 타겟 근육을 한눈에 보게 해줘.
     - 본인 패키지 잔여 회차 프로그레스 바, 방문 회차별 관리 요약(관리사 내부 메모는 철저히 숨기고 고객 공개 코멘트만 표시) 확인
     - 관리사가 방금 배정한 홈운동 가이드/영상 확인 및 [오늘 운동 수행 완료 체크] 버튼 동작 구현
  ```

3. 계약 성사 후 실제 납품 시점(Step 6)에 `supabase/schema.sql`을 고객사 Supabase 프로젝트에 실행하고 환경변수(`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`)만 연결하면 정식 클라우드 DB 버전으로 전환됩니다.
